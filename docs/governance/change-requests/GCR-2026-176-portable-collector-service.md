# GCR-2026-176 — Persistent portable collector and VM selection

Date: 2026-11-15. Status: implemented candidate for review; no live consumer or publisher activation.

This increment follows GCR-2026-175 / PR #371. Classification under the [artifact intake process](../../operations/processes/new-artifact-intake-process.md): additive collector service, persisted native task queue in the existing SQLite database, bounded transport cache, serial candidate publisher, VM engine selection, Workbench projection, schemas, fixtures and deployment integration. This is technical implementation under the portability Goal, not a normative governance source.

The collector discovers completed native runs including failed governance results, resolves physical GitHub/GitLab job IDs, stores immutable producer receipt identities alongside physical task identities, and invokes the same native capture and real OPA verifier as CI/local intake. Duplicate physical-to-producer aliases and ambiguous GitHub jobs are held. Throttle, hourly ceilings, profile cursors and restart recovery are persistent. Raw evidence precedes replay consumption; backups retain queue tables and migration lineage.

Candidate publication uses reviewed routing and node binding, at least 24 hours of shadow observation plus a newly produced exact committed mainline comparison, fresh evidence, a frozen maximum of 25 candidate documents, one active batch including legacy work, native all-state PR/MR reconciliation and immutable Git commits. No fetched central code or tests are executed during synchronization. Source drift requires an application update. A merged proposal remains a reviewed candidate; it does not become an official result or compliance approval.

The default registry and routing are empty, the central endpoint is unconfigured, deployment preserves the legacy engine by default, and the example private configuration is paused. An explicitly selected portable profile uses the existing isolated systemd account and operation schedules. Reader and publisher credentials are separate; the poll unit never receives publisher credentials. State migration/activation and installation on the actual VM remain separate authorized operations. Unsupported schema downgrade is rejected before stopping services. Internal source mirrors can be configured without credentials in their URL.

Architecture governance, historical releases, protected pilot fingerprints, current accepted indexes and the running Mac/VM remain unchanged. Capacity measurements, prepared offline distribution, version-specific live provider acceptance, authority profiles and complete Goal acceptance remain subsequent work. The local implementation and disposable systemd fixtures are not production compatibility or throughput evidence. See the [operating guide](../../operations/guides/portable-consumer-service.md) for exact boundaries and recovery steps.
