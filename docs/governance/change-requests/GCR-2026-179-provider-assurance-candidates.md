# GCR-2026-179 — Provider assurance candidates and context boundaries

Date: 2026-11-15. Status: technical implementation candidate under portability WP6–WP8.

Classification under the [artifact intake process](../../operations/processes/new-artifact-intake-process.md): additive provider issuer/subject, review and self-security capability contracts, candidate-only read models, context-bound shadow hardening and disposable VM migration/update/recovery tests. No normative source, role assignment, live operating acceptance or baseline change is created. Existing accepted GitHub lifecycle/profile/publisher paths remain unchanged.

The collector's shadow handoff must establish a native **default-branch** producer run. A `push` on an arbitrary branch is insufficient. The additional private context proof is bound to the captured native repository metadata, bundle and verifier; immutable producer receipts and public candidate formats are retained. Unknown/other default branches cannot fulfill mainline shadow acceptance. This closes an ambiguity in the earlier candidate implementation before any real publisher activation.

New provider profiles remain candidates with no live authority. Issuer/subject identity never substitutes for role/approval acceptance. Equivalent native capabilities are explicit; unavailable or provider-specific criteria remain unproved. New candidate indexes remain separate from official domain results and the retained demo. The disposable Ubuntu harness additionally exercises stopped-writer legacy migration, explicit portable engine selection, backup/retained records, restart and rejected incompatible downgrade; actual Proxmox operation remains separate.
