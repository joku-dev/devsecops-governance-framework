# AXIOM V2 operational publisher

`operational-publisher publish/inspect/replay` retains the complete V1
`publish_operational_update.py` behavior at source revision
`6b557fefe295b58272d2271326576ca3a3687197`. Publishing is a one-shot native write
operation, selected explicitly by the caller. It does not start a publisher
service, resume a failed operation or transfer operating authority from source
history. Current full source, cross-version, installed and consumer acceptance
remain open; the parity entrypoint stays `in_progress`.

## Whole behavior and provider boundary

The five neutral original functions preserve all original ledger/common/scope
constants, allowlisted selection, ancestry, staging, commit, push, proposal and
CI dispatch order. The sixth complete function, the original POST helper, lives
in the explicit provider adapter. The legacy profile owns environment names,
bot identity, URLs, endpoint/workflow names and proposal wording. The selected
source's programs are not imported or executed by this product. Original source
fixtures and whole-function AST checks remain engineering references only.

The six scopes remain lifecycle pilot, synthetic lifecycle, DevSecOps,
architecture, typed evidence and portfolio. Unrelated generated files are
omitted; other out-of-scope changes, symlinks and edits to existing evidence are
rejected. Fetch and the original ancestry check precede branch creation. The
exact selected stage set is committed and pushed to the run/attempt automation
branch. The original core then requests a PR and three CI workflows; it never
merges or force-pushes Main.

The shared gate context uses the complete repository lifecycle model and real
accepted-prefix, fresh receipt, action and operating checks. Lifecycle-pilot
publication retains the original active/inactive checks, including
permission-reducing withdrawals. Synthetic publication checks accepted history,
pilot, overview and viewer in their original order. Read-only gate captures,
explicit schema resources and temporary/exclusive resource release use the same
ordered journal as publisher operations.

## Explicit command and declared context

A fresh admitted node is required for publishing and owned inspection. Example
structure, with separately configured provider credentials and operating scope:

```sh
axiom-v2 --instance /private/node operational-publisher publish \
  --profile legacy-operational-publisher-v1 \
  --transport-profile legacy-operational-publisher-native-v1 \
  --source-worktree /path/to/separate/operational-worktree \
  --scope portfolio --repository owner/repository --run-id 42 --attempt 1 \
  --workflow-ref refs/heads/main
```

`--workflow-ref` is a declared original execution input. It does not attest
platform protection or authorize the node. Default invocation runs the entire
original `main`, including its parser and protected-ref check. `--invocation
publish` selects the original callable. `--original-arguments` retains the
original argument list, including original help/errors; the subject stays bound
before native effects. Only public declared execution metadata is persisted;
credentials and the full native environment are not copied into the request.
Explicit original Git actor variables remain commit metadata, not human consent.

Optional `--output-file` and `--summary-file` select owned CI append targets
outside the source and node. `--schema-resource URI FILE` supplies explicit gate
resources. `--native-temporaries` selects actual temporary gate files; the
default projects those temporary files privately. Native Git/POST publication
still executes in either temporary mode.

For isolated native acceptance, the distinct
`legacy-operational-publisher-local-test-v1` transport requires
`--local-origin-root` and admits only owned local bare origins beneath that
root. It is a declared test profile, not a sandbox or production acceptance.
The native profile rejects a local test origin override.

## Real gates and partial outcomes

Each original native command has durable intent before execution, its exact
original and actual arguments, bound source/Git identity and working directory,
program identity, process start/terminal/cleanup observations and raw stdin,
stdout and stderr. Raw POST input stays bound to the original JSON call.
Captured process results are observations; remote completion is not separately
authenticated. Additional Git configuration/identity guards are technical
admission checks, not extra original business verdicts.

Selected CI append sessions retain original open/write/close ordering, complete
preimages, byte prefixes, buffering, modes, returned character counts and error
leaves. This includes a shared output path, missing parent, directory target,
UTF-8 data and original encoding failure. No owned append is replayed natively.

A PR failure can leave a pushed branch. A later dispatch failure can leave a
branch, PR and appended CI outputs. Original failures remain complete records
when all needed observations were captured. Missing observations, native
deadlines or lost journal completion remain incomplete and have no invented
original exit code. There is no automatic retry, resume or rollback. The receipt
shows the original return value and whether native writes may have occurred.
The inherited record field `published: false` describes the private record; it
does not assert that no remote proposal was created.

Neither an unchanged source acceptance nor recorded synthetic consent grants
this node operating, personal, producer or governance authority. Journals prove
retained local consistency, not producer authentication or external completion.
The node's collector can remain paused during an explicitly invoked one-shot
proposal; no persistent publisher is activated by the command.

## Inspection and pure replay

```sh
axiom-v2 --instance /private/node operational-publisher inspect --record /path/to/record
axiom-v2 operational-publisher replay --record /path/to/record
```

Inspection checks node/product binding and the closed journal. Source-free
replay reconstructs all original control flow using stored raw observations,
without Git, provider calls, source reads, temporary files or append effects.
The selected source and tools may be absent. Foreign-node owned inspection,
changed products/requests/results/streams/targets, forged authority and orphan
blobs are rejected. Successful inspection/replay means the retained original
outcome is consistent; an original failure is still displayed as a failure.

## Additional native admission conditions

The writer profile accepts an owned standalone clone, bounded ordinary outputs
and finite commands/streams/journals. Linked/shared Git directories, external
configuration, source filters and aliases need explicit additional profiles.
Before Git commands, the adapter checks configuration that could invoke source
commands; before writes, it checks bounded Git entries and remote binding.
Hooks, fsmonitor, pager, credential helpers and source SSH/receive/upload
commands are disabled or replaced by fixed settings. Recursive submodule fetch
and automatic maintenance are disabled. Selected source/node programs cannot be
used as executable tools. These conditions narrow native admission and are not
original findings or parity proof outside the admitted profile.

Checks are bounded observations, not OS network/process isolation or protection
against a concurrent configuration writer. Git state and process results do not
independently prove every external side effect. Native failures may have partial
effects. Profiles for aliases, external conversions, wider operating conditions
and additional providers remain explicit unfinished work.
