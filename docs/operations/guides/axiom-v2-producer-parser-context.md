# Producer parser context for retained executions

A retained execution reconstructs its original producer's parser, rather than
using the replay host's terminal width or translations. This engineering
candidate extends the existing ledger/documentation/candidate implementation to
the prior synthetic lifecycle reporting, workbook import and document renderer
APIs. The original program bodies, argument selection, file/tool effects and
original exits remain in scope. Current full regression, declared review and
signed installed Mac/Linux comparisons remain delivery requirements.

## Covered commands

| Command | Original parser scope |
| --- | --- |
| `synthetic-lifecycle` | All five complete index/pilot/exception/overview/viewer programs |
| `workbook-import` | Complete workbook import, including lazy selected paths |
| `document-rendering` | Complete renderer; Pandoc/tool environment remains separately retained |
| `synthetic-ledger` | All six whole original demo/intake programs |
| `documentation-reconciliation` | Complete original documentation/Git/append program |
| `lifecycle-candidates` | Both whole preparation programs and shared writer/adapters |

Every execution request requires `parser_context`: schema version1, CPython
implementation/version, explicit complete parser profile, observed formatter
width and `stdlib-en-v1` translations. Native capture admits the exact complete
stdlib module identities observed in pinned Python3.11.18 (CI),3.12.3 (Linux)
and3.13.18 (Mac), also checking formatter defaults and English singular/plural
translations. A version label alone does not admit an arbitrary or modified
Python distribution. Unknown modules or translations require an explicit new
profile and fail before record creation or selected-source observation.

Pure execution selects the complete retained producer parser/group/action/help
implementation. Its width and translations are explicit inputs; it consults no
consumer terminal, gettext/ngettext function or final retained stdout. All three
complete modules retain their original function/class bodies except the declared
explicit-width, English-translation and same-value SUPPRESS-identity composition
changes, with accompanying full PSF licenses and provenance notices. Each
composition verifies their whole code/license closure. Fixed original parsers
admit no implicit argument-file expansion channel.

## Execution admission and metadata-only validation

The prior reporting request validator also served as a shared finite metadata
shape check for the ledger and lifecycle-candidate commands. These roles are now
explicitly separate. `request_fields_valid` checks only the original common
metadata/resource shape; it neither executes nor admits a complete execution
request. Each public capture/replay validator requires and validates its own
producer parser context. Ledger/candidate bridges validate that context first
and use the metadata-only helper for their shared shape. Missing context has no
consumer-native default. Direct source-level core compatibility calls remain a
separate unrecorded native interface, not a portable product record.

Help/parser exits preserve the original streams and exit values without selected
data/schema reads or original output effects. The document renderer's own
private scratch preparation and observed tool environment remain separate from
original selected outputs and tool invocation. Selected tools are never run by
portable replay. Resealed context or final-stream changes must still reconstruct
the complete original result; normalization and copying stored stdout are not
valid substitutes.

## Historical records and acceptance

A new regression on an older synthetic pilot help record passes at columns80,
fails whole-result comparison at columns40 and passes again at80. The bytes and
closed event chain were unchanged; the old request lacked producer parser
context. Earlier fixed-host/fixed-width component proofs remain their original
dated observations. They do not establish all-environment Goal completion.

Historical records are preserved without relabeling or automatic migration.
Current records require their declared product generation and full context;
older product generations retain their own read scope. Adding parser inputs
neither authenticates a producer nor grants governance, personal or operating
authority. Full22areas/135entrypoints/37CIdefinitions/16operatingflows remain in
the Goal; no new verified receipt or released-baseline change is implied.
