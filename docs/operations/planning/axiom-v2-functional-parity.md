## Subject receipts and evidence delivery

A matrix state is a technical declaration. A row may become `verified` only after
its whole original helper/CLI/default/effect scope and explicit differences have
been audited, with actual positive, negative and installed evidence. Aggregate
suite counts or an installed symbol alone do not prove that scope. All areas,
CI definitions and operating flows remain part of the full Goal.

The parity checker reads public receipt metadata from
`config/axiom-v2-parity-evidence/` by default. That directory is included by the
existing configuration distribution root. Each matrix reference selects one
bounded JSON file by ID and pins its complete SHA-256. Reading receipts performs no directory enumeration, native command, provider
call or private input publication; an explicit original-source audit separately
uses local read-only Git commands.
`--evidence-directory` explicitly replaces that source; a missing or invalid
operator receipt never falls back to a packaged copy. With no verified rows,
no receipt directory is required.

The closed `axiom-v2-parity-receipt.schema.json` retains the five minimal V1
technical-declaration fields for an explicit operator directory: schema version,
subject, kind, passed and current runtime digest. Packaged metadata additionally
requires the declared evidence kind, frozen V1 reference, hash-only evidence
sources and false authority/independent-human/official/production flags. Where
the matrix supplies original source and installed implementation identities,
the public receipt must also bind their actual hashes. Optional observed source
revision/tree and finite case counts are metadata, not execution authentication.

Only hashes and byte counts of named technical evidence classes are allowed;
private review bodies, raw inputs, arbitrary file paths and authority claims are
rejected. The underlying files and review plans/results remain private. The
coordinator must actually inspect source, tests, logs, comparisons and operating
boundaries before producing these declarations. The checker verifies structural,
subject, source/runtime and byte bindings; it cannot authenticate an author,
prove semantic test quality or grant human/operating approval from a hash.

Receipt and matrix reads are bounded held regular single-link files, with change
observations and strict duplicate/nonfinite JSON rejection. Missing, stale,
changed, symlinked or invalid evidence stops the audit. The report pins the exact
matrix bytes with `matrix_sha256` and reports the evidence source and number of
receipts checked. Runtime source is checked before and after the audit. Both
matrix and receipt metadata are excluded from that runtime digest to avoid a
circular assertion; reader and schema changes remain included. A changed runtime
needs fresh matching evidence, never relabelled earlier receipts.

Adding this delivery mechanism alone promotes no row. New source requires its
own full and installed checks before a subject decision. A missing original Git
reference still prevents full completion, and `--require-complete` continues to
fail while any original subject remains unfinished.

## Intake records and retry preparation

`intake-records attempt/event/retry/inspect/status` restores the original
collection-failure recorder, intake-operation event recorder and controlled
retry-plan preparation. `--repo` explicitly selects an external existing ledger
root; `--profile legacy-intake-records-v1` selects the native compatibility
adapter. The installed product and its private node state cannot be destinations.

```sh
python scripts/axiom_v2.py --instance /private/operator/v2-instance intake-records attempt \
  --repo /private/operator/intake-checkout --profile legacy-intake-records-v1 \
  --repository-id owner/repository --run-id 42 --evidence-type governance_result \
  --collector-id central-governance-intake --artifact-name governance-control-evaluation \
  --error-code intake_failed --message 'Operator-declared failure' --retryable

python scripts/axiom_v2.py --instance /private/operator/v2-instance intake-records retry \
  --repo /private/operator/intake-checkout --profile legacy-intake-records-v1 \
  --attempt-path status/collection-attempts/owner__repository/retained-attempt.json \
  --native-output /private/operator/retry-output.txt
```

The attempt command preserves every original option, including `--api-url`,
`--token`, collector version, partial/failed status and retryability. Actual HTTPS
metadata acquisition uses the original endpoint path, headers, timeout and 16 MiB
response bound. Native token defaults remain in the adapter: explicit token,
then `GH_RESULT_INTAKE_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN`. Use protected environment
credentials where possible; command-line values may be visible in process lists.
The endpoint is operator-selected, HTTPS only and without URL credentials.
Authorization is stripped on a cross-origin redirect; HTTPS downgrade is rejected.
Credentials are never intentionally retained. The private response may contain
provider metadata and must be treated as private evidence.

Metadata failure retains the original warning, fallback identity and additional
retryable error. Successful metadata remains a provider declaration: the original
unchecked returned run ID and other native fields are preserved, including a
possible schema-invalid record. `native_schema_valid` is diagnostic for attempt
and event recording; the original writers do not reject these records. Retry
preparation does validate the native schema before selecting a route.

The event command keeps all original source/collector/intake/type/status/error/
time options. Native CI environment defaults are adapter-owned. Required timezones,
UTC second-resolution output and duration computed from full-precision input are
preserved. `--at` makes evaluation time explicit; otherwise the system UTC clock
is recorded. The outer `assessed_at` is the assessment start. A separate retained
`native_time` preserves the original phase: normal attempts sample after metadata
resolution; default event completion samples before ledger scanning. Its value,
source and phase are checked during offline reconstruction without reading the
clock again. An explicit `--at` uses its declared value; an explicit
`--completed-at` supplies the event completion directly without a native clock
sample. This corrects the earlier attempt timestamp sampled before metadata I/O.
Success/partial/failure are operator/environment declarations and
do not authenticate whether a real intake happened.

Records preserve the first matching identity in sorted file order. Repeating the
same record is a no-op; changed content under that identity retains an append-only
conflict. An existing conflict leaf is kept as opaque first evidence. Filename
collisions append repeated `-retry` suffixes. As in V1, stdout is the originally
requested relative filename even if an earlier matching file is selected; the
receipt distinguishes `requested`, `selected` and `ledger_effect`.

Rejected API bases, including an explicitly empty value, produce the original
warning and fallback attempt rather than aborting before recording. Unsafe URL
credentials are neither queried nor retained; only a rejected-selection marker
is stored. An omitted base alone selects the original default endpoint.

Retry preparation accepts only the original three governance/architecture/
vulnerability routes, retryable errors and safe repository/run/artifact values.
It prints the whole original JSON plan, or appends ordered native `key=value`
lines when `--native-output` (also `--github-output`) is given. Existing bytes,
mode and repeated invocations are preserved, including no inserted newline or
deduplication. The output parent must already exist; a missing parent fails
without creating it or printing a successful plan. The command performs no
workflow dispatch or accepted index update.

Before native access, an immutable private input and pending intent retain the
selected repo bucket. Conflict selection adds at most one explicitly named leaf
in a successor input linked to that original input. Other repos' conflict files
are never enumerated. Repo buckets and shared output paths have separate local
locks; common immutable blobs are stored once. The current bound is 4,096 relevant
files / 128 MiB per bucket snapshot and 16 MiB per file, response or native output.
These bounds are explicit operating limits, not a measured large-estate capacity.

Held directory/file descriptors, exclusive creation and change observations protect
history; owned regular single-link native output may be appended. Symlinked ledger
scan entries, hardlinks, nonregular files, Git metadata and unsafe writable output
are rejected. An explicitly selected retry-input alias may resolve to a held
ordinary file within the selected attempt root, preserving original resolution.
New files/directories are private. This narrows unsafe V1 filesystem cases and
makes failures diagnostic exit 2 instead of exposing raw tracebacks. Local locks
and optimistic checks require one operating owner across independent nodes; they
are not a distributed lease or an atomic multi-file transaction. A concurrent or
partial write remains visible and is never silently undone or repeated.

`--format receipt` exposes the private assessment instead of native stdout.
`inspect --assessment ID` rederives complete successful native bytes from retained
inputs, response and before/after files without requerying the provider or caller
ledger. `status --operation ID` reports pending/incomplete effects and never resumes
a write. Client invocation is observed, while authenticated native outcome,
independent delivery, official index changes and authority remain false. Retained
hashes provide local reconstruction, not independent authentication or approval.

## Owned native process cleanup

Review execution and local attestation share an explicit POSIX process-group
adapter. Every signal targets the group started by that invocation, and waits
are bounded. Confirmed group absence is cached so later cleanup does not signal
a potentially reused group ID. Native process observations retain the cleanup
permission-denial flag and its absence-check result; offline reconstruction
rejects inconsistent pairs and an unproven cleanup cannot become complete.

A reproduced macOS race returns `EPERM` for a group already absent from the
process table, including for signal zero. On macOS only, the adapter may handle
that denial after a bounded, strict `/bin/ps -A -o pgid=,state=` observation finds
the group absent or containing only defunct members. The observation must also
contain the live observer's own group. Live members, malformed/incomplete tool
output, tool failure and unknown visibility remain errors. Linux permission
denials remain errors without this process-table exception. Read-only `ps`
output is transient and is not retained in private assessments or public metadata.

The regression evidence includes the original full-suite failure, isolated
actual denied-signal reproduction, synthetic positive/negative cleanup contracts
and a 400-invocation owned-child stress check with no late writes. This narrows
the demonstrated cleanup race; it does not retroactively classify every earlier
runner failure. Fresh full-suite and installed checks are still required for
each candidate, and cleanup observations grant no execution or approval authority.

## Local attestation pilot

`attestation verify/inspect/status` restores the separate original public-key
attestation pilot. It is a diagnostic report-only flow, independent of typed
evidence's native producer/provenance verification. The original ordered checks
are registered pilot root/repository, signature, subject and context. A compatible
local crypto tool performs the actual signature check through an explicit port;
the neutral decision function receives its observation.

```sh
python scripts/axiom_v2.py --instance /private/operator/v2-instance attestation verify \
  /private/operator/attestation.json --output /private/operator/assessment.json \
  --trust-roots /private/operator/pilot-registry.yaml \
  --evaluated-at 2026-11-18T00:00:00Z --profile legacy-attestation-pilot-v1
```

All original options remain: positional attestation, `--output`, `--trust-roots`
and `--evaluated-at`. The default registry is the product's existing pilot data;
omitting evaluation time uses the system UTC clock as V1 did. `--expected-context`
and `--expected-subject` expose the helper's explicit expected values, while
`--effective-level` preserves a supplied legacy level label. Default expected
context/subject are taken from the statement itself, exactly as in the original
CLI; those comparisons are not independent producer authentication. The original
CLI summary, complete report and exit **0 even for findings or a missing tool**
are preserved. `--format receipt` returns the private diagnostic assessment.

The caller-selected output must be outside product/instance and Git metadata.
New files are private; an existing owned, single-link regular file is overwritten
in place with its mode preserved, as in V1. Its exact previous bytes and stat
observation are retained before crypto/write. Durable private intent precedes
effects; a changed destination fails without reverting another writer's edit.
Same-node writers serialize. Independent nodes need one operating owner per
external destination; optimistic checks are not a distributed lease or a fully
atomic file compare-and-swap. A partial/interrupted write remains visible and is
never automatically retried. Caller input/output aliasing is supported through
retained input bytes; output symlinks, hardlinks, nonregular or writable-by-other
files are rejected. Input aliases resolve to bounded regular readable files.

```sh
python scripts/axiom_v2.py --instance /private/operator/v2-instance attestation inspect \
  --assessment <assessment-id>
python scripts/axiom_v2.py --instance /private/operator/v2-instance attestation status \
  --operation <operation-id>
```

Private input manifests preserve exact JSON/YAML and old/new output bytes. Safe
YAML aliases, merges, duplicate-key last-value behavior and inert safe metadata
retain the pilot's ordinary SafeLoader meaning; this is separate from stricter
review-contract parsing. Composition/expansion/cycle/depth budgets run before
construction. JSON retains original duplicate/nonfinite value semantics within
bounded input graphs. Native output bytes and stdout are rederived on inspection,
using retained process observations and no current caller files or crypto calls.
`cryptographic_signature_reverified: false` makes that replay boundary explicit.

The native profile uses fixed OpenSSL verification arguments, no shell/network
API, private staging and actual binary path/hash, process/return-code and bounded
stdout/stderr observations. A compatible OpenSSL supporting the original
Ed25519 `pkeyutl -verify -pubin -rawin` command must be supplied through the host
tool environment. This optional external tool is not installed by the command.
The Mac's bundled LibreSSL may not support those arguments; original generic
native failure messages do not distinguish unsupported tools from bad signatures.
Fresh host acceptance records the actual compatible tool version and SHA-256.
Missing executable behavior remains the original explicit not-performed result;
timeouts/tool changes/stream overruns stop with diagnostic exit2 instead of a
fabricated signature verdict. Current limits are input/output1MiB, key64KiB,
decoded signature16KiB, process streams64KiB each and execution15seconds.
Both local process adapters close all pipe handles even when process cleanup
itself raises an exception; the review adapter also releases its held directory
descriptor. A cleanup error remains a partial failure with observed actual start,
without a completed review/signature verdict or automatic retry. Fault-injection
tests verify this boundary independently of normal process termination.

The original pilot does not enforce registry dates or its `algorithm` metadata;
this legacy profile preserves that behavior and states those limits explicitly.
Its `effective_level` is a preserved declaration; the surrounding V2 diagnostic
remains `evidence_trust: unverified`, `registry_authority_activated: false`, with
no accepted-root, operating, production or human approval. Neither the old demo
registry nor its public example is activated as a new node's Trust authority.
Formal subject and product parity acceptance remain separate.

## Optional review execution

`review-run` restores the original optional `run_agent_reviews.py` flow through
neutral orchestration and an explicit native CLI adapter. A clean committed
target with its own role/skill/routing/protocol, execution contract and provider
adapters is required. The external plan must cover the whole branch against an
exact base; an earlier V2 plan assessment is optional. Both Git object formats
are supported. The unchanged real consumer currently lacks those review
contracts; this remains an original rejection boundary, without injected roles.

```sh
python scripts/axiom_v2.py --instance /private/operator/v2-instance review-run run \
  --repo /private/operator/review-target --plan-file /private/operator/plan.json \
  --output-dir /private/operator/new-private-run \
  --profile legacy-codex-role-review-v1 --at 2026-11-18T00:00:00Z
```

The default prepares the original per-role schema/prompt/command files and root
results/execution files without starting a provider. `--plan` is retained as an
alias for `--plan-file`. Only an explicit `--execute` starts the selected native
provider, which may consume account credits; CI execution is forbidden. The
provider adapter owns model configuration, exact read-only/no-approval/ephemeral
arguments and native events. There is no shell or arbitrary executable argument.
`--parallel-specialists` defaults to 1 (contract maximum 3) and
`--timeout-seconds` to 180 (maximum 600 per role). The Steward runs after all
specialists complete, including the zero-specialist case; failed specialists
skip synthesis. No validators, retries or additional agents are launched by the
runner itself. A provider response declaring `completed` remains a declaration.

`--validation-results` supplies already recorded validation rows; the runner
neither executes checks nor invents successful outcomes. Default stdout retains
the four native summary fields and exits 0 for preparation/declared readiness,
1 for completed but incomplete execution and 2 for input/source/outer failures.
`--format receipt` exposes the private assessment and operation IDs instead.

The new output directory must be outside target, product checkout and private
instance. Native artifacts stay there; separate node-owned input snapshots,
durable intent, process-start observations, progress and retained raw artifacts
live under `state/review-execution/`. No external artifact is overwritten.
Exceptions preserve actual partial files, including original typed-YAML prompt
serialization failures. Inspection distinguishes complete reconstruction from
partial capture. A stopped/pending operation never authorizes an automatic retry.

```sh
python scripts/axiom_v2.py --instance /private/operator/v2-instance review-run inspect \
  --assessment <assessment-id>
python scripts/axiom_v2.py --instance /private/operator/v2-instance review-run status \
  --operation <operation-id>
```

Offline inspection verifies retained bytes and rederives complete native control
outputs without caller files, a current target or provider access. Opaque raw
streams remain private. It does not confirm native/model identity, factual
review quality, current Git state, human approval or production authority.
Original `provider_attempted` means execution was requested; the separate
`provider_invoked`/process-start facts record actual local starts, including
post-spawn failures that V1 could incorrectly label as unstarted.

The explicit resource/privacy profile additionally bounds responses to 1 MiB,
each output/error stream to 10 MiB, native files to 16 MiB and retained output to
512 MiB/3,000 files. Model/reasoning arguments are limited to 64 KiB each.
Native subprocesses use umask 077 and owned process groups are terminated on
completion or timeout before capture. Symlinks, hardlinks, nonregular/public
outputs and changed directories are rejected without reading unrelated bytes.
These protections are recorded V2 differences, not fabricated original behavior.
The source tests use a controlled local synthetic executable; no paid/live
provider or actual role review is implied. Full subject/installed parity remains
in progress until the corresponding evidence is complete.
